# WebMCP Behavioral Eval Baseline (2026-10-04)

Baseline measurement for the WebMCP behavioral eval against the production site.

## Baseline framing

This baseline was captured **after** the #1632 pagination change landed and **before** the remaining #1624/#1625 work. When #1624 and #1625 ship, the same harness runs unchanged against the same three tasks to produce the delta.

## Methodology

- Harness: `scripts/webmcp-eval/harness.ts` (PR #1638)
- 3 tasks (`discover`, `extract`, `traverse`) x 3 models x 5 iterations = 45 runs
- Models: `anthropic/claude-haiku-4-5`, `zai/glm-5.3-flash`, `openrouter/openai/gpt-6-luna`
- Fixed decoding: `GOOSE_TEMPERATURE=0.3`, `GOOSE_SEED=42`, `--max-turns 12`
- The site is served from `dist/` over localhost (secure context required by WebMCP); Chromium is launched with `--enable-features=WebMCP --enable-blink-features=WebMCP`
- The in-browser tools (`search_posts`, `get_post_markdown`, `get_related_posts`, `get_posts_by_concept`) are exposed to goose through a local streamable-HTTP MCP bridge speaking MCP 2026-07-28 sessionless discovery only. At capture time the bridge also served `subscribe_email`; that tool was removed from the site in PR #1644 and no eval task used it, so the capture remains comparable to today's four-tool surface.
- Each run is graded by a deterministic rubric over bridge-recorded tool payloads plus the goose final response
- No retries; genuine rubric FAILs are kept as data. Only infra failures (browser, flags, auth) would invalidate a run; there were none.

## Environment

- Date: 2026-10-04
- goose 1.53.0
- Playwright 1.63.0 / Chromium 153.0.8010.12 (headless)
- Bun 1.4.0, macOS arm64

## Results

Full data: `docs/audit/baseline/` (45 run JSONs and `summary.md` generated by `scripts/webmcp-eval/summarize.ts`).

Pass rates (rubric, 5 iterations per cell):

| Task | claude-haiku-4-5 | glm-5.3-flash | gpt-6-luna |
| --- | --- | --- | --- |
| discover | 5/5 | 5/5 | 5/5 |
| extract | 4/5 | 5/5 | 5/5 |
| traverse | 5/5 | 5/5 | 5/5 |

Capture history: an earlier capture produced 7/15 `traverse` failures because the prompt did not disambiguate which cluster to use and the seed post `ai-observability-gaps` belongs to two clusters. The harness prompt was amended (PR #1638) to name `governance-oversight`, and the artifacts above are the post-fix rerun; the pre-fix artifacts were deleted.

Observations:

- `traverse` now passes 15/15. Every run answered with the terminal hub slug (`ai-sdlc-governance-stack`) after calling `get_related_posts` then `get_posts_by_concept` with `governance-oversight`, confirming the earlier failures were prompt ambiguity, not multi-hop reasoning or tool failure.
- The single rubric FAIL is `claude-haiku-4-5` on `extract` iteration 1: the final response did not quote the required claim verbatim and relied on page traversal instead of the paginated retrieval pattern the rubric expects.
- Token cost is still dominated by `extract` (full-post retrieval with pagination); `gpt-6-luna` is the cheapest per run on every task, `claude-haiku-4-5` the most expensive on `extract` due to larger per-page payloads in context.

## Delta procedure

Rerun unchanged:

```sh
bun run scripts/webmcp-eval/harness.ts \
  --output-dir docs/audit/<date>-delta --iterations 5
bun run scripts/webmcp-eval/summarize.ts --run-dir <delta dir> \
  --out <delta dir>/summary.md
```

and compare pass rates, tokens, and wall clock per cell against this baseline.
